## 一、模型陣容定案（Sonnet 歸隊）

之前把 Sonnet 拿掉是因為它夾在 Opus 與 Pro 中間、位置尷尬。現在重新評估，它在**進階版的降級緩衝**這個角色上很稱職，所以歸隊。

| 模型 | in/out (USD/MTok) | 每回合成本 (NT$) | 定位 |
|---|---|---|---|
| Opus | 5 / 25 | ~1.12 | 頂級文筆，最貴，子配額 |
| **Sonnet** | **3 / 15** | **~0.70** | **Opus 用完後的高品質緩衝（同 Claude 文風）** |
| Gemini Pro | 2 / 12 | ~0.52 | 量能主力、保底 |
| Haiku | 0.8 / 4 | ~0.18 | 便宜走量 |
| Lite | 0.1 / 0.4 | ~0.02 | 最便宜、日常／快速段落 |

### 加 Sonnet 的真實理由

現行設計是 Opus 子配額用完直接掉到 Gemini Pro，落差有感——調查裡很多人就是衝著 Claude 文風來的，換成 Gemini 會「出戲」。中間插一層 Sonnet，降級鏈變成：

```
Opus（極致·子配額）
   ↓ 用完
Sonnet（高品質·仍是 Claude 文風）
   ↓ 用完
Gemini Pro（走量保底）
```

文風滑落從「Claude → Gemini」的斷崖，變成「Opus → Sonnet → Pro」的緩坡。成本上 Sonnet 比 Opus 省一半、只比 Pro 貴一點，當緩衝層划算。

**提醒：** 別讓進階版模型多到難管。三段 Claude/Gemini 混搭是清楚的上限，不要再加更多層。

### 為什麼中階 NT$79 對

- 對 BYOK A（NT$49）的落差變成 30 元，淨收約 76 vs 48，「我幫你出 AI 額度」的溢價站得住。
- 滿用打平更有餘裕（用計算機可即時驗證）。
- **但最乾淨的區別不是價差，是賣不同的東西**：中階＝開箱即玩（不用碰金鑰、不用設定）；BYOK A＝用自己的鑰匙換自由（不限模型、用量看自己的金鑰）。79 vs 49 不是同物比價，是兩種人。定位語要跟上，別讓使用者覺得「不就是貴 30 塊的同一個東西」。

## 三、伺服器端模型路由：後端自由切換、玩家不知情

**可以，而且這是你「後端代呼叫」架構的天生能力。** 玩家完全不會知道用了哪個模型，因為他根本沒有指定模型的權力，也看不到回應來自誰。

### 3-1 為什麼玩家天生看不到

```
玩家送出訊息
   ↓ 只到「你的後端」，不是直接到 Anthropic／Google
你的後端決定這一回合用哪個模型
   （依方案 allowlist + Opus/Sonnet 子配額剩餘 + 降級規則）
   ↓
後端用對應金鑰呼叫該模型的 API
   ↓
只把「故事文字」回傳前端（不含模型名稱、不含 usage）
```

三個關鍵事實：

1. 玩家的請求裡**沒有也不能有**「我要用哪個模型」的欄位。模型選擇權只在後端。
2. 後端回應給前端的，**只有故事文字**——不夾帶 `model`、不夾帶 `usage`、不夾帶任何引擎指紋。
3. 「Opus 額度用完，這回合默默改 Sonnet」對玩家是透明的，他只看到故事繼續。

### 3-2 必守的鐵則

| 鐵則 | 為什麼 |
|---|---|
| 模型選擇只在後端 | 前端若能傳「我要 Opus」，免費用戶就能盜用付費模型 |
| allowlist 按方案驗證 | 後端收到請求先查「這個方案能用哪些模型」，擋越權 |
| 子配額計數在後端 | Opus 用了幾回、Sonnet 用了幾回，全在後端算，玩家改不了 |
| 回應不回傳引擎資訊 | 連 `usage`、`model` 欄位都不要送到前端 |

你後端的 `models.js`（集中路由）＋ allowlist ＋ preferredModel 驗證本來就是為這個設計的，這題對你是現成能力，不用新架構。

### 3-3 降級判斷的伺服器端邏輯（示意）

```javascript
function pickModel(user, todayUsage) {
  const plan = user.plan;

  if (plan === 'advanced') {
    if (todayUsage.opus < OPUS_SUBQUOTA)   return 'claude-opus-4-8';     // 第一段
    if (todayUsage.sonnet < SONNET_BUFFER) return 'claude-sonnet-4-6';   // 第二段緩衝
    return 'gemini-2.5-pro';                                             // 第三段保底
  }
  if (plan === 'mid') {
    return todayUsage.total < MID_LITE_QUOTA ? 'gemini-flash-lite' : 'claude-haiku-4-5';
  }
  if (plan === 'free') {
    return todayUsage.total < 5 ? 'gemini-flash-lite' : 'claude-haiku-4-5';
  }
  if (plan === 'byok') {
    return user.byokPreferredModel; // 用他金鑰，可開放他選
  }
}
```

呼叫後**只更新對應模型的子計數**（原子操作），並只把文字回前端。

### 3-4 要不要讓玩家「知道」自己在用哪一段——這是產品選擇，不是技術限制

你有三種做法，按沉浸程度排：

| 做法 | 體驗 | 適合 |
|---|---|---|
| **完全隱藏** | 玩家永遠不知道引擎換過 | 最沉浸，貼你的美學 |
| **額度用完時溫和提示一次** | 「今日的頂級文筆額度已用盡，故事將以標準文筆繼續」 | 避免玩家在高潮處發現文風變了卻不明所以 |
| **角落淡淡標示「文筆模式」** | 進階用戶有「我在用好東西」的感知 | 想讓付費感更有體感 |

**建議：完全隱藏，或在 Opus 額度用完那一刻溫和提示一次。** 後者較好，因為——

> 一個誠實的但書：玩家看不到「模型名稱」，但**夠敏感的重度玩家可能「感覺得出」文風變了**（調查裡就有人能分辨 Opus 與 Sonnet）。這不是洩漏，是品質差異本身。所以降級鏈要讓落差盡量小（這正是加 Sonnet 緩衝的價值），並在切換點給一句溫和提示，比讓他在劇情高潮處默默踩到落差好。

| 主題 | 一句話 |

| Sonnet | 歸隊，當進階版 Opus 用完後的高品質緩衝，文風落差變緩坡 |

| 是否告知玩家 | 產品選擇非技術限制；建議完全隱藏，或額度用完時溫和提示一次 |
| 架構影響 | 無新架構；沿用 models.js 集中路由＋allowlist＋子配額計數 |
